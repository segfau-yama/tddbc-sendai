# モルック：レビュー・設計・テスト計画

## 対象と完了条件

- 対象：`Throw`、`Skittle`、`Score`とJUnitテスト。
- 仕様：[STEP.md](../STEP.md)のSTEP 01・02。
- 1本なら番号、2本以上なら本数、0本なら0点を返す。
- 有効な投てきだけを生成し、生成後に状態を変更できない。
- 得点は0点から始まり、複数回の投てきの点数を合計する。
- 空のテストを残さず、Gradle Wrapperで全テストを実行する。

## レビュー時点の問題

| 優先度 | 問題 | 根拠 |
| --- | --- | --- |
| 高 | 複数本の点数が常に0点 | `(5, 8)`は仕様上2点だが0点を返した |
| 高 | テスト2件が空 | 複数本・0本を検証せず、成功として集計していた |
| 高 | 複数本で範囲検証を省略 | 単独では拒否される0・13が、複数入力で受理された |
| 中 | 期待値と実測値の順序が逆 | `assertEquals(実測値, 期待値)`で失敗時の表示が逆転する |
| 中 | 重複・nullの扱いが未定義 | 入力の判断を仕様とテストに残す必要がある |

## 設計と判断理由

- `Skittle`は番号を持つ不変の値オブジェクトとし、Java 17のrecordを使う。
- `Skittle(int number)`は1〜12以外を`IllegalArgumentException`で拒否する。
- `Throw(Skittle... fallenSkittles)`は、生成済みの`Skittle`を受け取る。
- 同じ番号のスキットルは1本だけなので、重複入力は例外で拒否する。
- `null`配列とnullの要素は入力不備として例外で拒否し、引数なしの投てきと区別する。
- `Throw`は検証済みの不変な集合を非公開フィールドに保持する。
- 集合を使うのは、番号の重複を検出し、入力順序に依存しないため。
- `calcPoint()`は状態を変えず、1本なら番号、それ以外は本数を返す。
- 外部から渡された配列は保持せず、変更が投てきに影響しないようにする。
- 呼び出し例は`new Throw(new Skittle(5), new Skittle(8)).calcPoint()`。
- 外部の利用者は見つからないため、旧static APIの互換ラッパーは追加しない。
- STEP 01の設計では投てきだけを扱った。得点の累積は末尾のSTEP 02で追加する。

## NullAwayによるコンパイル時のnull検査

### レビューと設計

- 高：Javaの参照型にはnullを代入できるため、コンストラクタの検証だけでは呼び出し側の誤用をコンパイル時に検出できない。
- Error Prone経由でNullAwayを実行し、違反は警告ではなくコンパイルエラーにする。
- JSpecifyの`@NullMarked`でmolkkyパッケージを非nullとして扱う。
- 配列・可変長引数・ジェネリクスの型注釈を扱うため、JSpecifyモードを有効にする。
- JDK 17を維持し、Error Proneは対応する2.42.0に固定する。
- JSpecifyモードに必要なOpenJDK 17.0.19以降とコンパイラオプションを使用する。
- 通常のプロダクトコードとテストコードを検査し、意図的なnull入力テストの範囲だけを抑制する。
- 外部の未検査コードからの入力もあるため、既存の実行時検証と28件のテストを維持する。
